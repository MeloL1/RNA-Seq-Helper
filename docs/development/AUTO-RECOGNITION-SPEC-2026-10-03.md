# 自动研判：识别摘要与必要问题（交互规格）

状态（2026-10-03）：规格已用于首个低风险实现，并经两轮 Luna/MAX 静态审查加固。当前包含原文短摘录、受限 sidecar 读取、逐项确认账本和分析门禁连接。目标仍是让新手看懂软件实际读到的证据，再回答缺失的实验事实；允许先预览，但没有确认单位/尺度时不进入统计分析。本实现不代表已用多个真实项目验证识别准确率。

## 用户看到的摘要卡

每个候选表达表显示：

1. **软件目前能判断什么**：表达表用途、数值单位、变换尺度分别给结论，不把整张表压成一个含糊的“自动识别成功/失败”。
2. **证据来自哪里**：来源文件/工作表/字段或 GEO 元数据；展示支持结论的短摘录。数值外观、整数比例、范围和文件名只能说明线索，不能单独确认单位或 log 变换。
3. **下一步只问缺失事实**：单位已由明确元数据说明时，不重复问单位；log 状态已明确时，不重复问是否取 log。用户可以查看预览、打开来源说明或选择“不确定”。
4. **可修改且可追溯**：接受或修改后记录所选事实、证据位置、用户确认状态和已知转换公式/伪计数；不保存表达值到诊断文案、不上传数据。

建议文案结构：

> 初步判读：这张表的单位是「TPM」。依据：交付说明 / 工作表 Readme 的“TPM normalized expression”一行。软件据此建议按连续表达值处理。请确认这段说明对应当前工作表。
>
> 还需要确认：数值有没有取 log？查看交付说明中的公式或预览标题。若不清楚，可以先预览；确认前不能开始分析。

没有来源证据时，不显示“自动研判失败”或伪装成已判定单位。明确说出当前可观察事实和边界，例如：

> 初步判读：这是数值型表达表，有 6 列样本；文件里没有写单位，也没有写转换公式，所以现在无法区分原始 count、TPM 或芯片信号。请查看交付说明中的“数据类型/处理方法”。你仍可先看预览；不确定时先停在这里，不会按猜测开始分析。

## 证据等级与行为

| 等级 | 证据 | 界面行为 |
|---|---|---|
| A：直接说明 | 提供方 README/交付说明、表格明确元数据、GEO 处理说明中的单位/转换文字 | 显示结论、来源定位和短摘录；用户可一次确认整张摘要，也可改任一项。来源没有写到的字段继续提问 |
| B：可见线索 | 工作表名、列名、文件名、同工作簿 count/TPM sheet 命名 | 只作候选建议并写明理由。count 与 TPM 同时出现时可建议 count 优先用于 RNA-seq 差异分析；仍需用户对照交付说明确认 |
| C：没有可用文字证据 | 只有数值外观、整数/小数分布、大小范围、相关性或 PCA 形状 | 给出“表格可读取，但单位/变换未被文件证据说明”的结论；只询问缺少的事实，允许预览，不自动填成 OTHER_NORMALIZED/LINEAR，不放行统计门禁 |

不能把等级 B 的建议升级成等级 A；不能因证据为空而设置“其他连续表达值 + 原始/线性”以绕过门禁。用户显式选择“不确定”时保留未确认字段并说明仍可做什么、哪些分析暂不能做。

## 关键输入例子与验收条件

### A. 提供方写明 TPM，但没说是否取 log

- 摘要给出单位 TPM，附说明文件名、工作表/行位置和原文短摘录。
- 只问变换尺度；不重复问单位。用户可先预览。
- 用户回答“不确定”时保留尺度未知，整理页面显示具体阻断原因，不能启动分析。

### B. 同一工作簿有 `Counts` 与 `TPM` 两张表，说明页没有单位定义

- 可以把 `Counts` 作为优先查看候选，明确理由来自工作表名及 count 通常适用于 DESeq2 的分析路径。
- 不把 sheet 名当作已证实单位；仍要求用户核对数据交付说明。不得自动合并工作表。
- 若用户选 TPM，遵照用户选择，不因默认建议强行跳回 Counts。

### C. 文件只有一张数值矩阵，没有单位说明，也没有公式

- 明确说“能识别为可读数值表达表；无法从文件证据确认单位和转换”，不说“研判失败”。
- 显示一条简短必要问题，并给“去哪里找”指引（交付说明、论文 Methods、GEO 样本/处理说明）。
- 预览继续开放；数值门禁仍阻断整理完成/分析计划，直到用户按实验事实确认。

### D. 说明写有 `log2 normalized expression`，但未给伪计数/公式

- 记录有 log2 的文字依据；把底数记录为 log2，把伪计数/输入公式标为来源未说明。
- 只要求确认缺失的公式信息；不能从 log2 数值逆变换或伪造 `log2(x+1)`。只有已知变换足以匹配当前统计 profile 时才允许计划分析，否则解释尚缺内容。

### E. 分组表有 DZ、CA、YDW

- 若用户已明确 DZ=对照、CA=疾病、YDW=治疗，可作为这批样本的已知组别事实，并逐样本显示映射供确认。
- 不将三组自动折成任意两组；开始比较前要求选择有科学含义的两组/对比。组别映射不由文件名相似度单独确认。

## 确认与阻断契约

- 可读取、可预览与可分析是三个状态。缺失事实时仍可查看有限预览。
- `measurement_type` 和 `value_scale` 分别确认、分别记录来源；显式事实可一次确认摘要，修改后必须重算计划。
- 只有未知字段阻断，不要求新手重新回答已有直接证据支持的字段。
- 不确定不是产品故障：显示尚缺哪一项、为何影响方法选择、下一步去哪里核实；不以猜测放行。
- 分组推断不能替代实验设计事实；保留用户排除组的能力，不把未选择样本塞进对照或疾病组。
- 证据引用应限长、可定位，并避免把样本表达值、患者信息写入提示或常规日志。

## 实现状态与剩余边界

第一项低风险迭代：

- `ImportPage` 将候选摘要、软件线索/核查范围、当前先要确认的一项分开显示；用户选择单位后，提示切换到尚未确认的尺度，选择尺度后显示两项已选择。
- 对表格正文文字提示显示文件名、工作表（如有）及软件扫描范围（前 8 行、最多 80 列）。这表示“软件在哪里查找”，不是命中词原文或提供方结论；仍要求按交付说明核实。
- 无文字证据时按当前缺项提问，保留 UNKNOWN 门禁；没有改变扫描判断、统计 profile 或数值输入。
- 契约测试验证提示状态、来源范围和一步一问，不以合成数字评价生物学识别准确度。

2026-10-03 首轮证据实现：

- 表格只扫描预览前 8 行×最多 80 列的非数值文字单元格；命中后记录原文件、行列或工作表单元格和短摘录。摘录截断会显示省略号，已知对象标识及公式外数字做脱敏；数值大小、整数性、分布和 PCA/相关性不参与单位/尺度识别。
- 仅在同目录有限读取 README/说明/交付 `.md/.txt` 文件（最多 4 个、单文件 256 KiB、合计 512 KiB）；不解压、不联网、不跟随符号链接。文件须明确提及当前表名，或目录仅有一张表达表；多 sheet 时还须提及当前 sheet。无法关联的说明只提示“未用于判断”。候选冲突时该事实保持 UNKNOWN。
- “确认并采用文件原文候选”是显式用户动作；没有候选的字段仍 UNKNOWN。手动选择/覆盖、采用候选及未确认状态逐项写入整理配方和项目清单，并附来源摘录。
- 已发现的唯一完整 `log2(...)` 公式写入 `reported_transform`；未发现或存在不同公式时不补造伪计数，不写入统计输入用 `input_transform`。界面会提示查看 Methods/交付说明，并在缺失时如实记录。
- 对本机真实 GSE10361 Series Matrix 的只读复核结果为 UNKNOWN/UNKNOWN、无单位/尺度文字证据命中；这只支持“未知门禁保持有效”的结论。新增长测试检查解析与账本契约，不能证明不同供应商、格式和真实矩阵上的分类准确率。

2026-10-03 审查加固：

- 关联说明最多 4 份、单份 256 KiB、合计 512 KiB、3000 行、单行 8192 字符。只要说明文件枚举、读取、解码或范围检查不完整，整批说明证据就不参与候选共识，并禁用“一键采用”；不会把排在前面的几份当成完整扫描结果。
- 同值说明按单位/尺度候选去重，但保留不同候选和最多两种 log2 公式；超过两种已足以判定公式冲突。英文/中文常见否定写法不作为正向 log2 证据。确认按钮只接受摘要中实际展示且未脱敏的支持摘录。
- 公式字段只保留受限白名单表达式；被识别为患者/样本/临床身份上下文的整句不展示、不写入事实摘录，证据来源/位置及带明确身份标记的本地路径也会隐藏。可识别的路径标记包括 patient001、sample 01、样本-001 等形式。
- 脱敏属于标签/上下文规则，无法可靠识别没有任何身份标签的自然人姓名；样本列内容仍作为分析输入写入本地项目文件。项目应保存在用户控制的本机安全位置，不应将临床样本标识当作已自动匿名化。
- 新回归使用有限文字/路径字符串验证解析、冲突、脱敏、禁用和序列化契约，不使用合成表达值评价生物学分类。真实 GSE10361 的结果仍只是未知门禁负例，不是识别准确率验证。

剩余验证：用更多本地真实交付说明核实文件关联与术语覆盖；对相互矛盾的多个说明、公式差异与多工作表做独立审查；检查事实页长摘录/高对比与窄屏布局的实屏可读性；把尚未明确的公式、伪计数提供用户可审查的补录/来源字段。任何证据缺失、冲突或关联不明时继续 UNKNOWN，不得把范围说明当作证据原文。
